# BPM 流程管理操作手册

> 一句话说明：本工具用来管理各环境（dev/test/uat/prod）的 BPM 流程定义，支持把流程从服务器拉到本地、把本地修改推回服务器，以及把流程从一个环境复制到另一个环境（晋级）。

---

## 一、准备工作

### 1.1 安装 Python3

脚本需要 Python 3.6 或更高版本。

- **Windows**：访问 https://www.python.org/downloads/ 下载安装，安装时勾选「Add Python to PATH」。
- **Mac**：打开终端，输入 `python3 --version`，如果提示未安装，系统会引导你安装。
- **Linux**：通常已预装，输入 `python3 --version` 检查。

### 1.2 怎么运行脚本

| 系统 | 拉取流程 | 推送流程 |
|------|----------|----------|
| Mac / Linux | 双击或在终端输入 `./export.sh` | 双击或在终端输入 `./import.sh` |
| Windows | 双击 `export.bat` | 双击 `import.bat` |

> 第一次运行 Mac/Linux 脚本时，如果提示「权限不足」，先在终端执行一次：`chmod +x export.sh import.sh`

## 二、常用操作

### 操作 A：把服务器上的流程拉到本地（export / 拉取）

**什么时候用**：你想查看或备份某个环境的流程，或者想把流程复制到另一个环境之前先拿到本地。

**步骤**：

1. 运行 `./export.sh`（Mac/Linux）或 `export.bat`（Windows）
2. 按提示选择环境（输入数字回车）：
   ```
   选择环境：
     1) dev    http://192.168.1.182:30080
     2) test   http://192.168.1.182:30082
     3) uat    http://192.168.1.182:30084
     4) prod   http://192.168.1.182:30086
   请输入序号 [1]: 1
   ```
3. 选择要拉取的流程（输入数字回车，多个用空格或逗号隔开，直接回车表示全部）：
   ```
   选择流程：
     0) 全量（所有流程）
     1) pdp_plan_doc_common    通用文档审批
     2) pdp-review_udit2       问题整改
   > 1
   ```
4. 等待完成。流程文件会保存到对应环境的目录下。

---

### 操作 B：把本地修改推回服务器（import / 推送）

**什么时候用**：你在本地修改了流程文件，想把修改更新到服务器上。

**重要提醒**：推送只会更新「草稿」，不会自动发布。发布需要登录 BPM 后台手动点击「部署」。

**步骤**：

1. 运行 `./import.sh`（Mac/Linux）或 `import.bat`（Windows）
2. 按提示选择要推送到的环境（输入数字回车）
3. 选择要推送的流程（输入数字回车，多个用空格或逗号隔开）
4. 脚本会提示当前分类，一般直接回车保持即可
5. 看到 `是否只预览不推送？(y/N)` 时：
   - 输入 `y` 只预览，不会真的推送（适合先检查一遍）
   - 直接回车或输入 `N` 则正式推送

---

### 操作 C：把流程从 A 环境晋级到 B 环境（跨环境复制）

**什么时候用**：流程在 dev 环境测试通过了，要复制到 test 或 uat 继续测试；或者 uat 通过了要复制到 prod 上线。

**步骤**：

1. 先从 A 环境拉取流程到本地（见操作 A）
2. 把 A 环境对应流程的 `now` 文件夹复制到 B 环境的同名流程下：
   ```bash
   # 示例：把 dev 环境的「通用文档审批」复制到 test 环境
   mkdir -p "test/pdp_plan_doc_common - 通用文档审批"
   cp -r "dev/pdp_plan_doc_common - 通用文档审批/now" \
         "test/pdp_plan_doc_common - 通用文档审批/"
   ```
   > Windows 用户：用文件资源管理器手动复制粘贴即可
3. 对 B 环境执行推送（见操作 B），选择刚刚复制过去的流程

## 三、目录结构说明

每个环境（dev/test/uat/prod）下都有若干个流程文件夹，命名格式为：`流程代号 - 中文名称`

每个流程文件夹内部结构如下：

```
流程文件夹/
  now/                    ← 当前正在编辑的版本（可修改、可推送）
    xxx.bpmn              ← 流程定义文件
    model.json            ← 流程基本信息（名称、分类等）
    form.json             ← 动态表单（只有启用了动态表单的流程才有）
  v1/                     ← 历史版本 1（只读，不能修改）
    xxx.bpmn
    model.json
    form.json
  v2/                     ← 历史版本 2（只读）
    ...
```

| 文件夹 | 含义 | 能否修改 |
|--------|------|----------|
| `now/` | 当前版本 | 可以修改、可以推送 |
| `v1`、`v2`、`v3`... | 历史已发布版本 | 只读，留作备份 |

## 五、常见问题

**Q：推送后为什么在系统里看不到新流程？**  
A：推送只更新草稿，必须登录 BPM 后台找到对应流程，点击「部署」才会正式生效。

**Q：我可以直接修改 `v1`、`v2` 里的文件吗？**  
A：不建议。这些历史版本是只读的，修改后下次拉取会被覆盖。要改流程请改 `now/` 里的文件。

**Q：Windows 双击 bat 文件闪一下就没了？**  
A：先打开 CMD 或 PowerShell，把 bat 文件拖进去按回车运行，这样能看到报错信息。

**Q：Mac 提示「无法打开，因为无法验证开发者」？**  
A：打开「系统设置 → 隐私与安全性」，点击「仍要打开」允许脚本运行。
